Groove — System Architecture

A browser-based music production tool: pattern-based sequencing, real-time persistence, and a stable Tone.js audio graph, built around one canonical domain model that every other layer consumes through read-only projections and a typed command layer.

SolidJS 2 + @solidjs/vite-plugin (client start mode) · Vite · TypeScript (strict) · Zod · Tone.js · Firebase Auth + Firestore · Bun · Vitest / Playwright

The edit round-trip

Every project change follows one path, whatever the input device:

  1. Component builds a typed command (e.g. note.add) — it never touches the Project.
  2. CommandHistory.execute() (via EditorSession) runs the transaction: pure apply on a working copy, all domain invariants checked, pack dependencies recomputed.
  3. A new immutable revision replaces the store; undo gets the generated inverse command.
  4. ProjectAutosave coalesces the edit and queues only the changed tier — a note edit writes one clip document, never song structure.
  5. ProjectRepository performs the revision-checked write to Firestore (or the in-memory store under VITE_DEV_BACKEND=mock).
  6. watchProject delivers remote snapshots; applyRemote() ignores echoes at or below the local revision, and components update reactively.
  7. In parallel, useProjectAudio rebuilds the audio projection (reusing unchanged entries) and ProjectAudioGraph reconciles only the touched subgraph.

Load-bearing rules

  • Contracts are layered by import direction: domain and commands import no Firebase, Tone, or Solid; only firestoreProjectRepository.ts imports firebase/firestore; all Tone code stays in src/audio/.
  • One write path: registered commands via executeTransaction — no feature-specific mutation routes.
  • Stable IDs everywhere: persistent relationships use prefixed IDs; audio-graph reconciliation, undo replay, and Firestore documents all key on them.
  • Musical time is integer ticks at 192 PPQ; seconds, bars, and pixels are derived views.
  • Single audio context: AudioRuntime owns it; every constructed node is registered with a project scope so disposal is provable.
  • Analytics ships with features: events come only from the typed catalog, and no parameter ever carries a name, user text, URL, or token.
